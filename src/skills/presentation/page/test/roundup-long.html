01 TL;DR

The connection pooling rewrite landed this week and more than tripled P2P relay throughput — a bigger gain than expected. The token staking mechanism is now live on testnet, which is a major milestone for the token economy layer. Privacy layer work is progressing well but is turning out to be more complex than the initial estimate, primarily due to edge cases in the zero-knowledge proof verification path.

Testnet uptime
  • Connection pooling rewrite — replaced the naive per-connection socket model with a pooled architecture. Relay throughput went from baseline to 3× in the benchmark suite. Latency dropped from 31ms to 12ms median.
  • Token staking mechanism on testnet — the core staking contract is deployed and verified on our testnet. Validators can now stake and un-stake AUKI tokens. Slash conditions are implemented but not yet activated.
  • Relay node health monitoring — added structured health metrics to all relay nodes. Dashboard now shows per-node throughput, queue depth, and error rate in real time. Caught two nodes running degraded last week that we'd have missed otherwise.
  • P2P handshake protocol v2 — tightened the handshake sequence to reduce connection setup time by ~40%. Removes a round trip that was introduced as a workaround for a bug that no longer exists.

The relay throughput improvement was not targeted — it emerged from the connection pooling rewrite. We should revisit our throughput assumptions in the token economy model, as this changes the cost-per-relay calculation significantly.

03 What's in progress

Zero-knowledge privacy layer

The privacy layer is the most complex active piece of work. The goal is to let devices prove membership in a Domain without revealing their identity to the relay. The ZK proof system is chosen (Groth16 via snarkjs) and the circuits are mostly written. The blocker is verification time: on-device proof verification is taking ~800ms on a mid-range Android, which is too slow for the join flow. Exploring batching strategies.

Validator incentive design

Working with the tokenomics model to define how validators are rewarded for relay work. The core question is how to measure relay quality (not just quantity) — a validator that handles many low-quality connections should not earn more than one handling fewer high-quality ones. Three candidate models on the table; running simulations this week.

Cross-Domain transform protocol

Collaboration with Robin on the spatial layer. Defines how pose data transforms between Domains that share a physical boundary. The protocol is specified; implementation is blocked on agreeing the canonical coordinate frame convention with the spatial SDK team.

04 Blockers & asks
  • ZK proof verification latency — the 800ms on-device verification time is a hard blocker for shipping the privacy layer. Need input from anyone with experience optimising Groth16 verification on Android. If we can't solve this in the next two weeks, we may need to shift verification server-side, which has privacy implications we'd need to work through.
  • Coordinate frame convention — the cross-Domain transform work is blocked on Robin confirming the canonical spatial coordinate convention. This has been open for three weeks. Need a decision by end of next week or the timeline slips.
