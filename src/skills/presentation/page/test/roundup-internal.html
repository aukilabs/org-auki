Spatial SDK · Week 20

Pose conversion overhauled, Domain joining latency down significantly, and the perception pipeline now handles low-texture environments reliably.

01

TL;DR

We shipped a full rewrite of the pose conversion layer this week — the old implementation had accumulated enough edge-case hacks that it was becoming a reliability risk. The new version is cleaner, better tested, and resolves the coordinate-frame inconsistency that has been causing intermittent drift on ARKit sessions. Domain joining latency dropped from ~420ms to ~180ms as a side effect of the cleanup. The perception pipeline also got a significant fix: feature extraction now falls back correctly in low-texture environments, which unblocks the Gotu warehouse pilot.

Test coverage added
  • Pose conversion rewrite — replaced the patchwork coordinate-frame conversion with a single clean transform pipeline. Eliminates the ARKit drift bug reported in Week 18. Merged to main, ships in next SDK release.
  • Domain join latency — reduced from ~420ms to ~180ms. The improvement came from eliminating redundant handshake round-trips in the joining sequence — a consequence of the pose conversion cleanup rather than a targeted optimization.
  • Low-texture perception fix — feature extraction now falls back to a broader SIFT descriptor window when the primary ORB pass finds fewer than 40 keypoints. Tested against the Gotu warehouse environment; accuracy goes from 71% to 94% in that setting.
  • SDK documentation update — rewrote the pose conversion and Domain joining guides to reflect the new implementation. Removed two sections describing workarounds that no longer apply.

The Gotu warehouse pilot was blocked on the low-texture perception issue. That unblock is the most commercially significant thing this week — the pilot can now proceed as planned.

03

What's in progress

Temporal synchronization

Working on the clock sync layer for multi-device Domains. The current implementation assumes devices share a common time reference, which breaks in practice when clocks drift more than ~30ms. The fix involves a lightweight NTP-style protocol running at the Domain level. Design is done; implementation is ~60% complete. Main risk is the edge case where a device joins a Domain mid-session after significant drift.

Map persistence

Picking up the stalled map persistence work from Q1. The goal is to let Domains retain their spatial map across sessions so devices don't need to re-localize from scratch every time. The storage format is agreed; this week's focus is the load/merge logic for when a persisted map and a live map overlap.

Pose SDK API review

Going through the spatial SDK surface with DevRel following their report that Domain joining is the most common friction point for new developers. Mapping which parts of the API require understanding coordinate geometry to use correctly, with a view to adding higher-level convenience wrappers.
